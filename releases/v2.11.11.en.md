# Prompt Optimizer v2.11.11

## Summary
- Adds three solver-focused optimization templates (CTF, programming, forensics) in both Chinese and English, and rewrites the general, analytical, iterate and user-prompt templates into a solver task-brief structure.
- The Windows desktop app now uses a modern frameless window: the native title bar is removed, the system minimize/maximize/close controls are kept, and the title-bar overlay colors follow the active app theme.
- The product is narrowed to solver prompt optimization: the image-mode entry is hidden, and legacy image-mode preferences and routes fall back to basic mode.
- The in-app brand name becomes 解题提示词优化器 / Solver Prompt Optimizer across the zh-CN, zh-TW and en-US locales and the web and extension entry pages.

## Highlights
- With the three new templates you can turn a problem statement directly into a structured task brief for CTF (Web / Pwn / Reverse / Crypto / Misc / Forensics), programming and algorithm challenges, or forensics and data analysis; each template ships with direction-specific investigation paths and tool-chain hints.
- Optimized output is required to be conclusion-first and reproducible. The templates explicitly forbid inventing vulnerabilities or data, and degrade to a prioritized investigation checklist plus a list of missing information when input is insufficient.
- The Windows window is more compact: the whole header is a drag region with double-click to maximize, action buttons automatically avoid the system controls, and the title bar no longer shows a mismatched color band in light, dark, or any of the four additional themes.
- With the image-mode entry hidden, navigation and routing no longer expose the `/image/*` workspace, reducing accidental use.

## Product Updates

### Desktop
- On Windows, enables `titleBarStyle: 'hidden'` with `titleBarOverlay`, removing the native title bar while keeping the system minimize / maximize / close controls; the overlay is 36px tall. Non-Windows platforms are unchanged.
- Adds a `window-set-title-bar-overlay` IPC channel that only accepts `color`, `symbolColor` and `height`, validates them in the main process, and then calls `setTitleBarOverlay`; it returns a safe failure on non-Windows platforms or when the window is already destroyed.
- Exposes `electronAPI.window.setTitleBarOverlay` from preload and adds `WindowAPI` and `TitleBarOverlayOptions` to the renderer type declarations.
- Adds `packages/ui/src/utils/window-controls-overlay.ts`, which holds an overlay color table covering six themes across two surfaces (header and assistant-selection page) and only acts when `navigator.windowControlsOverlay.visible` is true, so it is a no-op in browsers and extensions.
- Makes the main layout header a drag region while excluding the navigation and action containers from dragging; the assistant-selection page is a bare layout and gets its own 36px top drag strip.
- Re-syncs the overlay colors per surface when routing switches between the main layout and the assistant-selection page, and whenever the theme changes.
- Enables `autoHideMenuBar` to hide the menu bar; the application menu and its accelerators (zoom, reload, DevTools, fullscreen) remain registered and functional.
- Hides the image-mode entry by default (`FunctionModeSelector` gains a `showImageMode` prop, default `false`).
- Falls legacy image-mode preferences back to basic mode so the hidden workspace can no longer be entered.

### Web
- Updates the entry-page title to 解题提示词优化器.
- The hidden image-mode entry and the route fallback also apply on web; `/image/*` is no longer a reachable default route.

### Extension
- Version is synced to 2.11.11 for this release, and the extension entry-page title is updated accordingly.

### Core/Infra
- Adds six built-in templates: `ctf-solve-optimize`, `programming-solve-optimize` and `forensics-solve-optimize`, each with an `_en` counterpart, registered in `ALL_TEMPLATES`.
- Rewrites six templates (`general-optimize`, `analytical-optimize`, `iterate`, and `user-prompt-basic / planning / professional`; 12 files including English variants) from a role-profile structure into a task-brief structure.
- Updates all three locales (zh-CN / zh-TW / en-US): brand name, launcher assistant description, prompt input placeholders and help text are now solver-oriented.
- Adds a `.tmp-verify/` rule to `.gitignore`.

## Fixes
- Fixes the window being undraggable in frameless mode by giving the main layout header and the assistant-selection page proper drag regions while keeping action areas `no-drag`, so interactive elements keep responding to clicks.
- Fixes the system window controls overlapping the header action buttons: when the overlay is active (`display-mode: window-controls-overlay`) the header reserves space on the right using `titlebar-area-width`.
- Fixes the title-bar color clashing with the UI after a theme switch by sampling colors per surface (header vs. page background) according to the current route.
- Fixes legacy image-mode preferences in history entering a hidden workspace; they now consistently fall back to basic mode.

## Breaking Changes / Upgrade Notes
- The image mode (`/image/*`) entry is hidden in this release: a saved image-mode preference automatically falls back to basic mode, and the image workspace is no longer reachable.
- The in-app brand name changes from "Frieren assistant" to 解题提示词优化器 (Solver Prompt Optimizer). Distribution artifact names and the repository name are unchanged.
- No user-data migration is required: custom model configuration, prompts and history are preserved as-is.
- Local development and builds still require Node.js 24.

## Developer Notes
- The release scope is `v2.11.10..HEAD`.
- Version syncing runs through `pnpm version:sync`, covering the root `package.json`, `packages/desktop/package.json` and `packages/extension/public/manifest.json`.
- Release notes follow the `scripts/release-notes.js` contract and can be validated with `pnpm release:notes:check v2.11.11`.
- The frameless-window work only affects the Electron Windows desktop app: `-webkit-app-region` and `display-mode: window-controls-overlay` have no effect in regular browsers, so web and extension behavior is unchanged.
- The new Chinese templates live under `packages/core/src/services/template/default-templates/`, which is an allowed prefix for `check:no-chinese-runtime`, so the language gate is not affected.
